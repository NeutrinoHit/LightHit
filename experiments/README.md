# Experiments: the registry of ideas and their measurements

Every idea tried in LightHit (a route, an option, a research module, a script)
has one file `ideas/<id>.toml`. The registry is the single place for tried
ideas; `REPORT.md` is generated from it and from the measured results. What the
default routes execute, function by function, is `../docs/usage-map.md`.

```text
ideas/<id>.toml           one idea: question, code, status, how to run, inputs, notes, [result]
run.py                    run measured cases, one process each, strictly one at a time
report.py                 check the registry, fold results into [result] blocks, write REPORT.md
REPORT.md                 generated: summary per idea and every measured case
map.py                    the idea map: ideas + plain_ru.toml -> map.html (open in a browser)
plain_ru.toml             short Russian name and plain outcome of every idea, for the map
map.html                  generated: tree by area and status, superseded chains, table, records
regenerate_inputs.py      NTSim/Geant4 events -> inputs/ (not in git)
photon_mc.py              NTSim photon Monte Carlo of one event -> inputs/mc/ (not in git)
photon_mc_point.py        NTSim photon Monte Carlo of an isotropic point source -> inputs/mc/ (not in git)
usage/                    usage tracer, scenarios, usage-map.json (-> docs/usage-map.md)
harness/                  inputs, references, metrics, provenance, case definitions
inputs/, results/         generated, not in git
```

## Registry fields

| Field | Content |
|---|---|
| `id`, `title`, `area` | name (= file name), one line, group (routes, shower, muon, core, tables, tools) |
| `question` | what the idea is meant to answer |
| `kind` | `route`, `table-builder`, `validation`, `probe`, `reference`, `alternative-option`, `tool` |
| `status` | `default` (what the default route does), `used-by-default` (a component, table or check of the default routes), `tool`, `superseded-by:<id>`, `rejected`, `open`, `not-reproducible` (with `not_reproducible_reason`) |
| `verdict` | one sentence from the measurements, written by hand after looking at `[result]` |
| `baseline` | the idea whose case on the same input is the speed baseline |
| `cases` | the measured cases (`idea/case`) of `run.py` |
| `how-to-run`, `inputs` | command and inputs |
| `notes` | facts from the code or from measurements in this registry only |
| `not_reproducible_parts` | optional: parts of an otherwise measured idea that cannot be rerun, each with its reason |
| `[code]` | `modules`, `functions`, `options`, `scripts`, `tests` |
| `[result.<case>]` | generated by `report.py`: date, commit, machine, threads, input hashes, timing, accuracy, script metrics |

Everything above the line `# ---- measured ...` is written by hand;
`report.py` rewrites only what follows it.

## Inputs

* The data bundle `$LIGHTHIT_DATA` (`lighthit-bgvd-data`): model, tables, the
  Geant4 100 GeV electron (events 0-9; event 5 placed at (5, -269.5, 330) m
  along (0.35, -0.20, 0.915) as in the stand-alone notebook), the 1 TeV muon
  with its ancestry, the 532 nm laser table.
* Events regenerated with NTSim (`python experiments/regenerate_inputs.py`, NTSim
  environment with Geant4; same seed 42 unless stated): 100 GeV electron, 1 TeV
  electron, 100 GeV pi+, nu_e CC (e 70 + pi+ 25 + p 5 GeV), nu_mu CC (mu 800 +
  pi+ 150 + p 50 GeV), muons of 100, 300 and 3000 GeV from (-100, -950, 350) m
  along +y, a 6 GeV stopping muon aimed past OM 267 and the same muon passing it
  at 1.76 m, the seed-43 1 TeV holdout muon, and `muon-1TeV-check`. NTSim
  reproduces the bundle 1 TeV muon bit for bit (`muon-1TeV-check`), so the
  regenerated 300 and 3000 GeV muons are the events the old research scripts used.
* The research scripts find inputs through `scripts/shower_basis/paths.py` and
  write below `results/work/` under the folder names they used before.

Two inputs are outside the bundle and used only where named: 321-frequency
directional tables (`$LIGHTHIT_RTE_CACHE_321`) for the full-table checks, and
`examples/point-green.toml`, restored from git (`ec553be~1`).

## References and metrics

* `reference-shower/<input>`: orders 0 and 1 on the original steps
  (`PromptConfig(element_method="segment", ballistic_method="interval",
  screen=False, fuse_bands=False)`), order >=2 by the per-band cloud-in-cell
  route (`transport_hybrid(ge2_basis=None)`), on the OMs active in the default
  route plus those with at least half the threshold, threshold 0, the default
  route's clock. `reference-muon/<input>`: the same with grouped per-band pencils
  for order 1 (all original steps, no screen).
* Photon Monte Carlo (`photon_mc.py`): NTSim CherenkovGenerator with every
  photon, MCPhotonPropagator with 30 scatterings, SmartRayTracer; compared per
  OM with its statistical error (`photon-mc-comparison`); per scattering order
  and distance, also for an isotropic point source (`photon_mc_point.py`), in
  `wavelength-quadrature`. The references above use the kernel's own
  wavelength quadrature, so its error shows only against the photon Monte
  Carlo and against finer quadratures (`wavelength-quadrature`).
  For a deterministic LightHit charge `L` and weighted MC charge `M`, the
  first-order error of `R = L/M` is `abs(R) * sqrt(sum(hit_weight**2))/M`.
  In `wavelength-quadrature`, `total_sigma`, `ratio_sigma` and the headline
  `order*_sigma` report this ratio error; `mc_relative_sigma` and
  `order*_mc_relative_sigma` retain the fractional MC error. Results measured
  before 2026-10-20 used the fractional MC error in `total_sigma` and
  `order*_sigma`; their charge ratios are unaffected.
  Default routes retain coarse order-1 charges on inactive OMs. The control
  `wavelength-quadrature/point-order1-screening` recomputes 100-250 m OMs
  without that screen before comparing a small tail with photon MC.
* Script ideas report the scripts' own metrics (the script's JSON, and its log in
  `results/<idea>/<case>.log`).
* Metrics against a reference (`harness/metrics.py`), per order and total:
  charge bias, bin L1 over OMs active in both, worst OM relative charge error
  (reference >= 0.01 pe), active-set agreement. Timing: wall and CPU of the
  timed call after one warm-up call in the same process (Numba compiled, tables
  loaded), peak RSS of the process.

## Running

```sh
export LIGHTHIT_DATA=/path/to/lighthit-bgvd-data
export PYTHONPATH=src
python experiments/regenerate_inputs.py                 # NTSim environment, once
python scripts/shower_basis/paths.py prepare            # legacy layout + ancestry of 300/3000 GeV
python experiments/run.py run 'default-*/*'             # baselines first (the references use them)
python experiments/run.py run 'reference-*/*'
python experiments/run.py run 'shower-*/*' 'muon-*/*'   # and so on; see `run.py list`
python experiments/report.py                            # [result] blocks and REPORT.md
python experiments/map.py                               # map.html from the registry
```

When an idea's verdict or status changes, update its line in `plain_ru.toml`
and rerun `map.py`.

`run.py run` fixes `NUMBA_NUM_THREADS`, `OMP_NUM_THREADS`,
`OPENBLAS_NUM_THREADS` and `VECLIB_MAXIMUM_THREADS` to 1 (`--threads default`
leaves them unset; such results are stored as `<case>@threads-default`). Run
one case at a time on an otherwise idle machine: every result records the load
average at its start.
