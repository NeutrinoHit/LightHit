# Один направленный фотон: учебная проверка переноса

Источник испускает один монохроматический фотон из начала координат вдоль
оси **+z**. Требуется независимо получить отклик среды аналитически,
уравнением переноса (RTE) и методом Монте-Карло. Здесь нет Geant4-ливня,
черенковского спектра, группировки заряженных частиц или готовых атласов OM.
Поэтому тест проверяет само ядро переноса и его численное разрешение.

Рабочие маршруты `ShowerTransport`, `MuonTransport` и их таблицы этот стенд
не вызывает и не меняет. Код находится в `lighthit.validation`; пример с
командной строкой — `lighthit.examples.pencil_validation`.

## Запуск

Из checkout, содержащего этот пример, в отдельном Python-окружении:

```sh
python -m pip install -e '.[validation]'
python -m lighthit.examples.pencil_validation --profile quick --output results/pencil-quick
python -m lighthit.examples.pencil_validation --profile full --output results/pencil-full
```

После установки доступна также команда `lighthit-pencil-check`. Python ≥3.11,
NumPy и SciPy нужны для RTE; Numba ускоряет независимый МК, Matplotlib строит
графики. Geant4 и модель реального детектора не нужны. Среда по умолчанию
синтетическая: μa=0.07 м⁻¹, μs=0.022 м⁻¹, HG g=0.9, ng=1.36, λ=450 нм.
Это пример, не калибровка воды.

`quick` предназначен для первого знакомства: 60 000 историй, две дальности,
несколько разрешений RTE. `full` использует 1.6 млн историй, 10/30/125 м,
независимые уточнения L, J, k, объёмной квадратуры, дополнительное опорное
решение, другие оценки МК и временной контроль. Это стенд проверки, а не
измеритель скорости полного события. Полный запуск может занимать несколько
минут; первая JIT-компиляция входит во время первого МК-вызова.

```sh
# Повторно использовать только массивы с теми же параметрами и хэшами кода:
python -m lighthit.examples.pencil_validation --profile full --output results/pencil-full --resume

# Собственный размер ансамбля, без графиков и временного контроля:
python -m lighthit.examples.pencil_validation --profile full \
  --photons-per-batch 80000 --batches 32 --no-time --no-plots \
  --output results/pencil-more-statistics

# При наличии экспортированной модели использовать только её воду при 450 нм:
python -m lighthit.examples.pencil_validation --profile full \
  --model path/to/model.npz --wavelength 450 --output results/pencil-water
```

Число историй и профили задаются до сравнения. Не следует менять семена или
выбирать разрешение только потому, что один вариант лучше совпал с МК.

## Что означает «сигнал в точке»

Случайное попадание рассеянного фотона в математическую точку имеет нулевую
вероятность. Вместо такого счётчика МК измеряет **скалярную флюенсность в
конечном объёме**. Ячейка задаётся интервалом радиуса r и косинуса полярного
угла μ=cos θ; азимут покрывает 2π. При направленном источнике, изотропной
среде и скалярном приёмнике есть осевая симметрия, поэтому азимутальное
усреднение не теряет информацию об угловой зависимости относительно оси.

Объём ячейки:

\[
 V=\frac{2\pi}{3}(\mu_+-\mu_-)(r_+^3-r_-^3).
\]

Каждая история даёт сумму взвешенных длин всех частей её траектории внутри
ячейки, делённую на V. Все повторные входы и выходы учитываются. После
деления на число испущенных фотонов единицы ответа — **м⁻² на фотон**.

Это не поверхность стекла, не поглощающий приёмник и не вероятность первого
входа. Для сравнения RTE усредняется **по тому же объёму**, а не берётся в
центре ячейки. Файлы `rte-cell-refinement.npz` и `point-centres.npz` позволяют
отдельно исследовать приближение точки.

Полярная шапка включает ось исходного луча. Её Q0 конечен после объёмного
усреднения. На самой оси направленного точечного источника ответ —
распределение, а Q1 имеет сингулярность. Шапка, сжимающаяся к оси, не имеет
обычного конечного точечного предела. Вне оси уменьшение ячейки должно вести
к регулярному точечному ответу. Именно там полезно сравнивать центр и среднее.

## Три порядка и аналитические контроли

Порядок означает число рассеяний **до измеряемого участка траектории**:
0, ровно 1, не менее 2. Поглощение не считается рассеянием.

- **Q0.** Вне исходной оси он строго нулевой. Для шапки аналитически
  интегрируется `exp[-(μa+μs−iω/v)r]` вдоль прямого луча и делится на V.
- **Q1.** RTE-решатель использует точный HG-интеграл в координатном
  пространстве. Дополнительная независимая квадратура по углу столкновения
  χ проверяет его значения в регулярных точках (`prompt_reference.py`).
- **Q≥2.** Здесь действительно проверяется спектральное RTE-решение и
  обратное пространственное преобразование при конечных L, J и k_max.

Полезен контроль **по всему пространству**, не зависящий от направления:

\[
 d=\mu_a+\mu_s-i\omega/v,\qquad a=\mu_a-i\omega/v,
\]
\[
 \int G_0\,d^3x=\frac1d,\quad
 \int G_1\,d^3x=\frac{\mu_s}{d^2},\quad
 \int G_{\ge2}\,d^3x=\frac{\mu_s^2}{a d^2},\quad
 \int G\,d^3x=\frac1a.
\]

При ω=0 сумма равна 1/μa, в метрах на фотон. Это отдельная размерность:
пространственный интеграл флюенсности. Эти формулы проверяются МК и RTE при
k=0. Частотная конвенция во всём стенде — `exp(+iωt)`.

### Конечный OM — отдельный контроль Q0

Для сферы радиуса R с центром (ρ,0,z) исходный луч пересекает стекло при
ρ<R и z>0. Расстояние до первого входа
`L=z−sqrt(R²−ρ²)`, вероятность безрассеянного входа
`exp[-(μa+μs)L]`. При ρ>R или расположении сферы позади источника Q0=0.

В отчёте этот контроль имеет единицы **вероятности**, эффективность и отклик
приняты равными единице. В МК независимо проверяется выживание до первого
входа. Это не основание сравнивать объёмное Q≥2 с сигналом на стекле;
поверхностные рассеянные атласы здесь не строятся.

## Как устроен независимый МК

В основном варианте длина свободного пробега выбирается с коэффициентом
**μs**, а поглощение учитывается весом `exp(-μa S)` и точно интегрируется на
каждом измеряемом отрезке. Направление поворачивается с распределением HG.
Пересечения сферических и конических границ находятся аналитически; между
корнями проверяется принадлежность ячейке. Ни RTE-матрицы, ни Bessel-функции,
ни готовые ядра этот код не использует.

Траектория не обрывается на фиксированной длине или числе столкновений.
При малом весе используется **русская рулетка**: фотон с весом w<ε сохраняется
с вероятностью w/ε и получает вес ε. Математическое ожидание сохраняется.
Порог ε меняет дисперсию и стоимость, а не физическую модель; отдельный
контроль меняет его на два порядка.

Для обратных слабых хвостов полный профиль предлагает смесь физических HG
и изотропных направлений. На каждом шаге вес умножается на **отношение
физической плотности к плотности предложения**. Поэтому усиленная выборка
не усиливает физический сигнал. Отдельный контроль использует только HG.

Ещё один вариант выбирает физическое расстояние поглощения и прекращает
историю при поглощении. Это аналоговая оценка, без непрерывного веса
поглощения. Она должна совпадать со взвешенной оценкой в пределах их ошибок,
но на больших расстояниях обычно имеет худшую статистику.

Для чтения кода без JIT можно вызвать
`estimate_cells(..., backend='python')` на небольшом ансамбле. Локальный
`numpy.random.Generator` не меняет глобальное состояние генератора NumPy.

## Статистика и численная сходимость

У МК сохраняются независимые блоки и вторые моменты **полных историй**.
Повторные посещения сначала суммируются, затем возводятся в квадрат.
Для суммы порядков ошибка считается после их сложения, с сохранением
корреляций. Указаны две оценки SE и эффективное число историй. Стенд заранее
использует максимум оценок SE по блокам и историям как консервативную
диагностику, не как строгую гарантию доверительного интервала.

Статусы строк отчёта:

| Статус | Значение |
|---|---|
| `structural_zero` | Q0 вне луча: оба ответа строго нулевые |
| `insufficient_histories` | нет достаточного числа эффективно измеренных историй |
| `statistics_limited` | SE МК больше заданной относительной точности |
| `resolution_limited` | опорное RTE-решение ещё чувствительно к уточнению сильнее цели |
| `discrepancy` | при разрешённой точности разность больше 3 SE |
| `consistent` | в этой точности разность не превышает 3 SE |

Порог по умолчанию 3% относится к этому **диагностическому эксперименту** и
не меняет численные допуски Q0 или настройки событий LightHit. Критерий одной
строки не является одновременной статистической гарантией всех строк.
Короткий ансамбль может дать отдельный большой pull; это не причина менять
семя, обрезать ошибки или нормировать ответ.

В RTE независимо уточняются:

- **L:** число гармоник оператора рассеяния HG;
- **J:** пространственное угловое разложение при обратном преобразовании;
- **k_max** и ширина k-панелей;
- радиальная и полярная квадратура усреднения ячейки.

L и J — разные ограничения. Свободный угловой хвост решателя не обрывается
на L. Профиль `event_bandwidth` показывает J=32 в этом опыте; это не полный
повтор event-маршрута с его источниками, чувствительностью и таблицами.
Сравнение с МК использует заранее заданное более строгое опорное решение;
чувствительность грубых профилей хранится отдельно. Наблюдаемый разброс
уточнений — оценка сходимости, не доказанная граница остаточной ошибки.

## Время и преобразование Фурье

Полный профиль дополнительно рассматривает одну регулярную ячейку на 30 м.
Сравниваются три кривые:

1. Исходная гистограмма МК по времени, построенная непосредственно из
   частей траекторий в ячейке.
2. Та же гистограмма после ограниченного частотного представления.
3. RTE после такого же частотного преобразования.

Различие первых двух характеризует частотный срез/восстановление, а не
перенос света. Дополнительно меняются шаг частоты и верхний срез, проверяется
укрупнение исходной гистограммы, доля заряда в окне и причинный фронт r_min/v.
Конечная частотная сетка может давать отрицательные колебания и повторения
с периодом `2π/Δω`; значения не обрезаются и не перенормируются.

## Результаты запуска и задания

В каталоге результата находятся:

- `REPORT.md`, `report.json`, `comparison.csv` — читаемая и машинная сводка;
- `mc-*.npz` — блоки МК, вторые моменты и, при запросе, временные бины;
- `rte-*.npz` — решения с полными настройками и хэшами входов/кода;
- `charge.png`, `geometry.png`, `convergence.png`, `time.png` — графики.

`--resume` не принимает массивы с несовпадающими параметрами или хэшами.
`--strict` возвращает код 1 при обнаруженном расхождении/нарушении
аналитического контроля, 2 при неразрешённой точности зарядных сравнений и 0
при выполнении этих критериев. Временная диагностика в этот код возврата не
входит: успешный `--strict` не доказывает сходимость формы импульса по верхней
частотной границе. Обычный запуск завершает отчёт независимо от научного
результата и не выдаёт все строки за «успешные».

Задания для самостоятельной работы:

1. Сравните L=24 и 48 при фиксированном J, затем J=128 и 256 при фиксированном L.
2. Уменьшите ячейку вне оси; сравните её среднее с точечным решением. Повторите
   для шапки и объясните, почему предел на оси отличается.
3. Измените поглощение; проверьте общую нормировку 1/μa и её частотный аналог.
4. Сравните физическую выборку HG и смесь с изотропным предложением. Объясните
   изменение дисперсии при сохранении среднего.
5. Сравните raw-гистограмму времени с её конечным спектральным восстановлением.
   Найдите, какой численный параметр меняет фронт, а какой — повторение сигнала.
6. Поменяйте источник на изотропный и g на ноль через программный API.
   Проверьте независимость полного сферического среднего от начального направления.

Измеренные результаты и ограничения приведены в `accuracy.md`. Этот стенд
проверяет ядро и оценки при заданных предположениях. Он не заменяет проверки
конверсии Geant4-шагов, спектра, геометрии OM и полного NTSim-трассировщика.
