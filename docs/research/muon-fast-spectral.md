# Ускорение спектрального мюона с вторичными частицами

Проверка 2026-09-28–29, NTSim `ToyGen` 100 ГэВ, PDG 13, один кластер BGVD
(288 ОМ), seed 42 и 43, одна поза `(5, -269.5, 330)` м. Среда, детектор,
длины волн и RTE-кэш те же, что в `spectral-shower-basis.md`. Приведены
отдельные процессы на одном Mac; времена одного запуска могут колебаться.

## Что тратило время

Исходный спектральный маршрут с явно выделенным мюоном `m=0`, 65
частотами и четырьмя потоками занял 145 с на seed 42. Из них:

| Работа | Время |
|---|---:|
| Prompt 0+1 | 22 с |
| Компиляция источника при ω=0 и на остальных частотах | 23 с |
| Применение RTE при ω=0 | 30 с |
| Применение RTE на всех частотах для активных ОМ | 69 с |

Геометрия содержит около 3 875 точек трека и столько же точек вторичных
частиц на каждой длине волны. Простое число G4-шагов не объясняет всё
время: одна и та же геометрия ОМ пересчитывалась для девяти спектральных
полос. Дополнительные потоки ускоряют независимые расчёты по ОМ.

## Проверенные изменения

1. **12 потоков Numba.** На этой машине дали 80.5 с вместо 145 с при
   практически той же памяти. 14 потоков не ускорили расчёт дальше.
2. **Общий геометрический проход для спектральных полос.** У мюонного
   трека все девять полос имеют одинаковые пространственные точки; у
   вторичных восемь из девяти. Новый Numba-проход считает ориентацию ОМ
   и вращение гармоник один раз для блока полос, сохраняя отдельный угол
   Черенкова и коэффициенты источника каждой длины волны. Полосы с другой
   сеткой точек считаются отдельно. Для ограничения памяти каналы источника
   внутри блока хранятся в `complex64`, трек объединяется до девяти полос,
   вторичные — по две. При 65 частотах результат занял 70.8 с и 5.3 ГиБ.
   Разница с раздельными полосами по заряду ≥2 менее
   5·10⁻¹⁰ ф.э. на проверенном событии.
3. **33 частоты вместо 65.** Подготовленный пакет на 65 частотах отдаёт
   каждую вторую частоту как представление без копии; новой сборки RTE
   нет. Интегральный заряд не изменился. Дополнительная L¹-ошибка формы
   ≥2 относительно 65 частот: максимум 1.49% на seed 42 и 1.78% на seed 43
   для десяти ярчайших ОМ. При 17 частотах ошибка выросла до 6.11%,
   поэтому такой режим отклонён.

| Seed | Общий спектральный базис, 65 частот | Быстрый трек + вторичные, 33 частоты |
|---:|---:|---:|
| 42 | 203.9 с / 7.7 ГиБ / 24 ОМ (4 потока) | 54.9 с тёплый; 62.5 с через NTSim / 3.9–4.4 ГиБ / 24 ОМ (12 потоков) |
| 43 | 120.5 с / 7.1 ГиБ / 28 ОМ (12 потоков) | 76.0 с / 4.9 ГиБ / 28 ОМ (12 потоков) |

Времена относятся к вызову LightHit после генерации G4-события; готовый RTE-кэш
занимает 1.2 ГиБ, пакет ядер ≥2 — 1.3 ГиБ на диске и не перестраивается.
Первый вызов может дополнительно включать прогрев Numba и отображённых
страниц. 12 потоков — измеренный выбор для этого Mac, не универсальный
оптимум.

## Точность быстрого режима против общего спектрального базиса

| Метрика | Seed 42 | Seed 43 |
|---|---:|---:|
| Активные ОМ | 24/24 | 28/28 |
| Макс. разница заряда ≥2 на ярких ОМ | 0.563% | 0.523% |
| Макс. L¹ бинов ≥2 на ярких ОМ | 2.413% | 2.669% |
| Макс. L¹ полного сигнала на ярких ОМ | 0.193% | 0.277% |
| Макс. абсолютная разница ранних 0–20 нс | 0.00144 ф.э. | 0.00124 ф.э. |

Prompt 0+1 и активные ОМ соответствуют тому же G4-событию. Разные числа
потоков дают лишь округление порядка 10⁻¹² ф.э. в prompt; порядок ≥2
при объединении полос отличается от раздельного расчёта на уровне
10⁻¹⁰ ф.э. Эти оценки относятся к внутреннему эталону с тем же
RTE-кэшем, угловым усечением и интерполяцией 65→321 частот; они не
доказывают абсолютную точность против независимого фотонного MC.

## Проверка через NTSim

Из корня NTSim; обёртка включает локальный checkout LightHit, подготовленный
пакет 65 частот и явные ключи `EventProcessor`:

```bash
bash run/check_spectral_basis.sh 13 fast-track
NTSIM_LH_SEED=43 bash run/check_spectral_basis.sh 13 fast-track
```

Для полного спектрального базиса на том же событии:

```bash
bash run/check_spectral_basis.sh 13 basis
NTSIM_LH_SEED=43 bash run/check_spectral_basis.sh 13 basis
```

Файлы разных режимов находятся в отдельных каталогах
`LightHit/.build/ntsim-check`. Сравнение нативных файлов из корня LightHit:

```bash
PYTHONPATH=src /Users/dmitrijnaumov/NeutrinoHit/ntsim_env/bin/python \
  scripts/shower_basis/verify_ntsim.py --method compare \
  --reference .build/ntsim-check/lighthit-hybrid-standard-freq65-pdg13-basis/event-0-hybrid-basis.npz \
  --candidate .build/ntsim-check/lighthit-hybrid-standard-freq65-pdg13-basis-track0-fused33/event-0-hybrid-basis.npz \
  --output .build/ntsim-check/muon-fast-comparison.json
```

Следующий физический выигрыш потребует более компактной модели вторичных
частиц: непрерывный световой ореол вдоль мюона плюс отдельные заметные
каскады. Такой источник нужно обучать и проверять на независимых G4-событиях;
текущий быстрый режим не подменяет их непроверенной параметризацией.
