# Спектральный базис ливня и запуск из NTSim

Проверка 2026-09-28 относительно LightHit `4bd04c1` и стандартного
`transport_hybrid`. Геометрия NTSim: один кластер BGVD, 288 ОМ;
электрон/мюон 100 ГэВ, seed 42, поза `(5, -269.5, 330)` м и направление
`(0.35, -0.20, 0.915)` после нормировки. Одни и те же вода, спектр,
RTE-кэш 3–300 м на девяти длинах волн и 65 частотах до 1.2 рад/нс,
readout в 321 частоте и бинах по 5 нс. Четыре потока Numba; BLAS/OMP —
по одному. Обычный гибрид остаётся маршрутом по умолчанию.
Подготовленный RTE-кэш занимает 1.2 ГиБ на диске, пакет ядер ≥2 — 1.3 ГиБ;
спектральный маршрут использует оба без новой сборки RTE.

## Источник и вычисление

Для каждого G4-отрезка \(i\) и длины волны \(\lambda\) проверяется порог
\(\beta_i n_\mathrm{ph}(\lambda)>1\) и берётся собственный угол

\[
  \mu_{C,i}(\lambda)=\cos\theta_{C,i}(\lambda)
       =\frac{1}{\beta_i n_\mathrm{ph}(\lambda)}.
\]

Коэффициенты того же пространственно-углового базиса вычисляются **для
каждой длины волны**, а не с одним углом 1.35:

\[
 c_{p\ell m}(\lambda,\omega)=
 \sum_{i:\beta_i n_\mathrm{ph}(\lambda)>1}
 \frac{C_i}{\lambda^2}
 \left(1-\frac{1}{\beta_i^2n_\mathrm{ph}^2(\lambda)}\right)
 W_p(\mathbf x_i)P_\ell(\mu_{C,i}(\lambda))
 Y_{\ell m}(\hat{\mathbf u}_i)e^{i\omega t_i}.
\]

\(W_p\) — осевые кубические срезы и поперечные моменты базиса.
Рассеянный отклик есть сумма свёрток
\(c_{p\ell m}G_{dp\ell m}^{(\ge2)}\) по \(p,\ell,m,\lambda\).
Готовый пакет радиальных RTE-ядер используется без
пересчёта; исходный RTE-кэш также не меняется. Источник компилируется по
одной λ: сначала только при ω=0 для выбора ОМ по полному заряду,
затем на 65 частотах лишь для активных ОМ. Это ограничивает память по
числу длин волн. Prompt 0+1 остаётся существующим спектральным решателем.

У двух мюонных вариантов разница заряда ≥2 на ярких ОМ ≤0.563%, бинов ≥2
≤1.741% L¹, полного сигнала ≤0.142% L¹. Prompt активных ОМ и все его
бины совпали побитно; один **неактивный** ОМ имеет небольшую разницу
заряда порядка 1 из-за приближённого отбора при `screen=True`.
Стандартный гибрид для всего этого длинного мюона отвергает источник по
старому радиальному условию; сравнение здесь выполнено с общим базисом,
использующим локальные окна 300 м.

Разница базиса и гибрида характеризует **источник и его дискретизацию**
при общем RTE-кэше, а не абсолютную ошибку переноса против фотонного MC.
Оба пути разделяют угловое усечение ядра и интерполяцию частот 65→321.
На мюоне ускорение остаётся умеренным: вторичные частицы занимают большую
часть длинного источника. Источники порядка 10 км требуют потокового
компилятора; здесь проверены события порядка нескольких сотен метров.
Последующий быстрый режим с 33 частотами, объединёнными спектральными
полосами и 12 потоками занял 55 с в тёплом повторе и выдержал проверку
на двух G4-событиях; подробности — в `muon-fast-spectral.md`.

## Воспроизведение через NTSim `EventProcessor`

Из корня NTSim на том же Mac; обёртка явно использует соседний checkout
LightHit, подготовленные RTE-кэш и mmap-пакет, а также `ntsim_env`:

```bash
bash run/check_spectral_basis.sh 11 reference
bash run/check_spectral_basis.sh 11 basis
bash run/check_spectral_basis.sh 13 basis
bash run/check_spectral_basis.sh 13 track
```

Запуски `13 basis` и `13 track` длительные. Результаты сохраняются в
`LightHit/.build/ntsim-check` с разными именами каталогов. Например,
электронное сравнение из корня LightHit:

```bash
PYTHONPATH=src /Users/dmitrijnaumov/NeutrinoHit/ntsim_env/bin/python \
  scripts/shower_basis/verify_ntsim.py --method compare \
  --reference .build/ntsim-check/lighthit-hybrid-standard-freq65-pdg11/event-0-hybrid.npz \
  --candidate .build/ntsim-check/lighthit-hybrid-standard-freq65-pdg11-basis/event-0-hybrid-basis.npz \
  --output .build/ntsim-check/spectral-basis-comparison.json
```

Нативный вызов `LightHitTransport(..., mode="hybrid",
hybrid_ge2_basis="shower")` использует тот же маршрут. Для первичного
мюона передайте также `hybrid_track_uid=0`; пакет ядер можно загрузить
через `hybrid_ge2_pack=...`. Выбор записывается в метаданные события.
