# Осцилляции временного профиля

Осцилляции около фронта — ожидаемое следствие конечной полосы частот, но их
величина является численной ошибкой, а не физическим сигналом. Скрипт
`scripts/study_time_ringing.py` отделяет три ручки на точном full-HG первом
порядке, для которого `single_bins` даёт независимый физико-временной эталон.

Контроль: синтетическая среда, $g=0.9$, $r=50$ м, окно 400 нс, бин 20 нс.

| сетка | относительная L1-ошибка | отрицательная масса / точное окно |
|---|---:|---:|
| $\omega_{max}=0.15$, 41 узел | 0.682 | 0.178 |
| тот же cutoff, 161 узел | 0.693 | 0.182 |
| $\omega_{max}=0.60$, 161 узел | 0.359 | 0.00589 |
| $\omega_{max}=1.20$, 321 узел | 0.280 | 0.00268 |
| $\omega_{max}=2.40$, 641 узел | 0.211 | 0.00194 |
| последний случай, бин 40 нс | 0.208 | 0.000411 |

Выводы различаются по роли параметра.

- Больше узлов при том же $\omega_{max}$ уменьшает $\Delta\omega$ и отодвигает
  периодические копии. В этом окне копии уже не мешают, поэтому результат почти
  не меняется.
- Больше $\omega_{max}$ действительно сужает band-limit ringing. Но первый
  порядок имеет логарифмически сингулярный фронт, его спектр убывает медленно;
  даже 2.4 нс⁻¹ ещё не воспроизводит весь фронт.
- Более широкий бин умножает спектр на более узкий sinc-фильтр и заметно
  подавляет чередующиеся отрицательные бины. Он теряет временное разрешение и не
  восстанавливает отсутствующую высокочастотную массу.

Именно поэтому точечный `PointGreenSolver` интегрирует порядки 0 и 1 напрямую
во времени. Для полного G4/axial-источника такого дешёвого координатного первого
порядка пока нет: viewer хранит исходные знаковые бины, отдельно показывает
заряд при $\omega=0$ и позволяет объединять соседние бины ×2/×4 без изменения
данных. Нельзя лечить ringing клиппингом или перенормировкой.

Воспроизведение:

```bash
python scripts/study_time_ringing.py --output .build/time-ringing
```

Числа находятся в `.build/time-ringing/report.json`, график — `ringing.png`.
